## 2. LLM workstream — findings

### Track A — `NeuroBridge_LLM_Project`
* `04_train_sft.py` targeted a newer TRL than the pinned `trl==0.15.2`. Fixes were made
  with `sed` that **removed `completion_only_loss`**, so the "v1" adapter trained on
  prompt tokens too, on **3 examples** (2 train / 1 val). Not a meaningful model.
* `07_train_sft_v2.py` (cell 59) correctly masks prompt tokens, using a plain `Trainer` +
  custom collator. It was trained on **33 examples for 1 epoch (3 optimizer steps)**:
  eval loss 2.34. Spot-check generations (cells 63–70) are still generic 10-item lists
  and get cut off. No systematic base-vs-fine-tuned comparison was run;
  `06_evaluate.py` needs an ORPO adapter that never existed.
* 440 diversity **prompts** (22 batches × 20, `NB001–NB440`) designed from a blueprint
  with 10 variation types. They passed structural audits, including one cross-batch
  duplicate bug that was found and fixed. Two schemas are mixed: 240 rows use
  `instruction`, 200 use `prompt`. **This is the most valuable asset in the notebook.**
* `neurobridge_candidate_responses_440.jsonl` (cells 107–108) was **generated by the v2
  adapter itself**, sampled at temperature 0.7 and capped at 220 new tokens. These are
  unreviewed outputs of a weak model, many truncated. Using them as SFT targets would be
  self-distillation of the model's own weaknesses. They were not in the replay (they need
  the model) and must be treated as candidates for review only.

### Track B — `NeuroBridge_LLM`
* `neurobridge_sft_12000.jsonl` is combinatorial templating (cell 114). Measured on the
  regenerated file:
  * 12,000 rows have only **768 unique instructions**, and the responses are built from
    **164 distinct lines**;
  * **3,000 responses (25%) contain a leaked instruction to the model** ("Keep the
    suggestions flexible and avoid assuming the user has the same needs as everyone
    else.");
  * **11,500 (96%)** contain the broken splice "Since you're dealing with X, Try …".
* SFT on it (cell 131) reached **train loss 0.23**, which is memorisation. The model
  reproduced the leaked instruction and the broken splice in its own evaluation output
  (cell 132).
* `neurobridge_orpo_1000.jsonl` uses **8 distinct rejected responses** for 1,000 pairs,
  all strawmen ("Just be more disciplined…"). This is exactly what the brief forbids;
  it teaches nothing defensible.
* **Seed set (39 records, 12 domains)**: 12 originals + 27 additions; a review pass marked
  31 KEEP / 8 REVISE; `neurobridge_seed_v2_revised.jsonl` has the 8 revisions with
  originals preserved. All `synthetic: true`, `human_reviewed: false`. Responses are
  292–452 characters; phrase audit shows "you don't have to / need to" over-use (21×).
  **Recovered intact and preserved.**
* Phase 2A (cell 149) generated 84 examples with the **base** Qwen model. The output file
  isn't saved in the replayable cells, and it is model-generated in any case.

### Cross-cutting issues
1. Training loss was the only metric. No held-out set shared between models and no
   safety probes; "improvement" was judged by eye on single samples.
2. `human_reviewed: false` everywhere. The "review" steps were done by the assistant
   that wrote the data, not by humans.
3. Package churn (TRL / bitsandbytes / pandas reinstalls) broke scripts repeatedly.
4. Paths, seeds and configs live in notebook cells; runs aren't reproducible from files.

## 3. Retain / improve / replace

| Asset | Decision |
|---|---|
| 39-seed set (+ revisions) | **Retain** verbatim as `raw/`; core SFT data |
| 36 v2 long-form examples | **Retain**; flag length (avg 2,171 chars) vs seed style (~377) |
| 440 diversity prompts | **Retain**; use as held-out **evaluation** prompts and as a response-writing queue |
| `07_train_sft_v2.py` masking approach | **Retain** the idea; rewritten as a configurable, version-tolerant script |
| 12,000 templated SFT / 1,000 ORPO | **Quarantine**: kept for the audit record, excluded from training by the pipeline |
| v2 candidate responses (440) | **Review-only**: never auto-promoted to training data |
| `04_train_sft.py` / `06_evaluate.py` | **Replace** with the pipeline's train/evaluate commands |

## 4. Prioritised plan (this batch = items 1–5)

1. Reproducible dataset pipeline: normalise, validate, clean, exact- and near-duplicate
   detection, template-leak detection, scenario classification, safety filtering, quality
   flags, leakage-safe split, SFT formatting, dataset card.
2. Structured evaluation: held-out prompts from the 440 + labelled safety probes;
   automatic metrics; blinded A/B human-rating sheets with scoring and confidence
   intervals.
3. QLoRA SFT script with response-only loss, fixed seeds, saved config and metrics.
4. ORPO readiness gate that rejects strawman pairs and requires SFT + evaluation evidence.
5. Model integration: local HF base/adapter provider, a development mock that is blocked
   in production, and an active-provider display.
6. *(Needs platform zip)* Audit the platform backend; then auth, profile, planner,
   journal, care circle, knowledge centre (RAG), admin, React frontend.
