# Dataset guide

## Where the data is

```
neurobridge_llm/data/
  raw/                       never edited; checksums in raw/MANIFEST.sha256
    seed/                    39-example seed set (12 domains) — v1 originals, additions,
                             review file, and seed_v2_revised (8 assistant revisions,
                             originals kept in `original_response`)
    v2_longform/             36 long-form caregiver examples (12 categories × 3)
    diversity_prompts/       440 scenario prompts (22 batches, NB001–NB440) + blueprint
    quarantine/              templated 12k SFT + 1k ORPO pairs (kept as audit evidence, gzipped)
  probes/safety_probes_v1.jsonl   24 labelled safety/behaviour probes
  reviews/decisions.jsonl         human review decisions (created by review-import)
  preferences/                    future preference pairs (see its README)
```

All of this was recovered by replaying the data-writing cells of `Untitled16.ipynb`, and
the recovered counts match the notebook's own validation output. Every training example
is **assistant-authored synthetic data**, with `human_reviewed: false`. Nothing here is
clinically validated.

## Build

```bash
cd neurobridge_llm
python -m nbllm.pipeline build                 # -> build/dataset_v1/
```

Outputs: `sft_train.jsonl`, `sft_validation.jsonl` (chat `messages`, versioned system
prompt), `eval_heldout_prompts.jsonl`, `records_all.jsonl` (every record with its flags),
`report.json`, `DATASET_CARD.md`.

Current build (`dataset_v1`): **75 training candidates → 64 train / 11 validation**, 0
excluded. There are 41 held-out evaluation prompts across 21 categories, with no overlap
with training prompts. The templated 12k set is detected (163 distinct lines across 12,000
rows) and excluded.

## Pipeline steps and what each catches

| Step | Check | Severity |
|---|---|---|
| validate | invalid JSON, missing prompt/response, too short | error |
| clean | Unicode NFC, whitespace, line endings | — |
| leaked instructions | text meant for the model appearing in responses ("Keep the suggestions flexible…") | error |
| template splice | "…dealing with X, Try …" artefacts | error |
| safety | dosing / medication-change / diagnosis statements; crisis prompts without a safety route | error |
| truncation, list-heavy, long | ends mid-sentence; > 8 list items; > 3,000 chars | warn |
| exact / near duplicates | normalised prompt match; word-3-gram Jaccard ≥ 0.8 clusters | error / warn |
| templated source | distinct lines per record < 0.1 over ≥ 50 rows | error (whole source) |
| repetitive openings | same 4-word opening in ≥ 4 responses | warn |
| scenario classification | keyword taxonomy; label/content mismatch | warn |
| split | cluster-aware (no paraphrase leakage), spread across domains, seeded | — |
| eval leakage | held-out prompts near-duplicating any training prompt are removed | error |

Warnings never remove data; they go to the review queue.

## Human review (the only way `human_reviewed` becomes true)

```bash
python -m nbllm.pipeline review-export --csv data/reviews/review_queue.csv
# reviewer fills decision(keep/revise/remove), revised_response, notes
python -m nbllm.pipeline review-import --csv filled.csv --reviewer "Full Name"
python -m nbllm.pipeline build
```

Set `"require_human_review": true` in `configs/dataset_v1.json` to train only on
reviewed examples.

## Expanding the dataset

The 440 diversity prompts are the best expansion source: write or curate responses for
them and add them as a new `train_candidate` source. Before doing so, move that prompt
subset out of the evaluation pool so evaluation stays held out. Do not use the 440
`candidate_responses` generated by the v2 adapter as targets without human revision:
they are outputs of a weak model, capped at 220 tokens.
